# Windows hosts

Host facts that broke a layer's helpers and tests on Windows machines, each with the failure it caused and what the layer does instead. `dev-init` reports the host's state in its pre-flight and changes nothing. A fact true of one machine only, such as a tool missing there, goes in a machine-local rule as the Intelligence engine's [decision 0021](https://github.com/ainova-systems/intelligence/blob/main/decisions/0021-local-and-targeted-source-artifacts.md) defines one, so it stays out of the project's committed rules.

| Host fact | Failure it caused | What the layer does |
|---|---|---|
| `make` may be missing, and `python3` may resolve to the Microsoft Store app alias in `WindowsApps` | A gate written as `make verify` stopped at "command not found" on a machine where the Node runner the target wraps worked | Helpers are dependency-free Node scripts started as `node <file>`; where a `make` target wraps one, the text a person or skill reads names the `node` call too |
| `process.exit()` ends the process with work still pending, and Node recommends setting `process.exitCode` instead ([Node docs](https://nodejs.org/api/process.html)) | Called right after a failed HTTPS `fetch`, it aborted in libuv while the sockets were closing, and the script exited 127 instead of 1, which a caller reads as "command not found" | A CLI wrapper prints one error line, sets `process.exitCode` and returns; its test stubs `process.exit` and asserts it is never called |
| Git prints paths with `/` (`C:/repo/x`), while `node:path` builds them with `\` | Comparing the two strings never matched: a guard that appended `/` to a backslash path missed, so a cleanup could delete another worktree's environment | Every path git prints goes through `path.resolve` before a comparison, prefixes are built with `path.sep`, and test expectations are built with `node:path` |
| A process that is not elevated can create a symbolic link only when Developer Mode is on ([CreateSymbolicLink](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createsymboliclinkw)) | `symlink` failed with `EPERM`, and every test that linked a file failed on that machine, whatever the change | On `EPERM` the helper copies the file; its tests inject a `symlink` that throws `EPERM`, so the copy path runs on every OS |
| An interpreter given its program on stdin may not read it: `python3 - <<EOF` started the Store alias's interactive prompt | One call waited on stdin until it was killed; another looped and wrote gigabytes of output | Code goes into a file that is then run, or the change is made with the edit tool. Never pass code to an interpreter through stdin or a heredoc |
| Git asks for credentials on the terminal unless `GIT_TERMINAL_PROMPT` is false ([git docs](https://git-scm.com/docs/git)) | An agent's `git fetch` sat on a prompt nobody could see until it was stopped | Every git command that reaches a remote runs with `GIT_TERMINAL_PROMPT=0`, so it fails instead of waiting |
| A path longer than 260 characters works in Git for Windows only with `core.longpaths=true`, off by default, and in other programs only with the `LongPathsEnabled` registry value set ([path limits](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)) | A checkout, worktree or fixture under a deep root fails in git or in the tool that opens it | Worktree and fixture roots stay short; setting either value is the owner's step |
| `core.autocrlf` decides line endings per machine wherever `.gitattributes` is silent | Contributors with different settings see every regenerated text file as modified | `dev-init` step 7 pins `eol=lf` |
