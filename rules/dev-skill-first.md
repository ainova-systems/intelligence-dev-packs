# Skill-First

## REQUIRED

- Before starting any task, check whether a skill in the catalog covers it (this pack's `dev-*` skills plus the project's own). If one matches, invoke it instead of improvising the workflow.
- When the same multi-step workflow has been improvised two or three times, propose extracting it into a project skill so the next run is codified.
- When a skill's steps no longer match reality (commands changed, flow changed), update the skill in the same change that changed the reality.

## Why this is the operating rule

- **Predictability**: output stops being a function of who prompted it. The task is done the project's way every time.
- **Onboarding**: a new engineer or a fresh agent session becomes productive by reading and invoking skills, not by absorbing tribal knowledge.
- **Compounding**: every codified skill is a reusable asset; team capability grows with the catalog.
